Chapter 1

What Hospital Information Retrieval System is

Hospital Information Retrieval System (HiRS for short) is an internal document repository. The application does two things at once: it keeps documents in an orderly folder structure and lets you ask questions about their content in plain language, the way you would ask a colleague who knows those documents.

The difference from an ordinary network drive is fundamental. On a drive you have to know which file to look in. Here it is enough to ask “what are the rules on remote work?” and the application finds the relevant passages itself, composes an answer from them and shows which document every sentence came from.

Two routes to a document

The application answers two different kinds of question and has a separate screen for each. AI chat answers questions about content — “from what age of a child is the subsidy available?”. Search answers questions about structure — “show all orders from 2023”. The split is deliberate: thanks to it you never have to guess which box your question belongs in.

What happens to a document after upload

Every document goes through automatic processing. The application reads its content (tables included), splits it into passages, recognises the kind of document — an order, a procedure, an application form — and extracts descriptive fields from it, for example a number, a date or the approving person. Only then does the document become visible to search and to chat.

Processing one document usually takes from a dozen seconds to a few minutes, depending on its length and on whether it is a text file or a scan that needs character recognition. During that time the document has the status Queued or Processing.

Data security

The whole application, language model included, runs on a server belonging to the hospital. Neither the content of the documents nor the questions asked ever leave that server, and nothing is sent to any external service. Access to documents follows from the permissions granted to the role an account belongs to — a user sees only the folders shared with them.

NoteThe application is a supporting tool. A chat answer always points to the source document, and it is the source document that remains binding — for formal matters, go to the document it indicates.

Chapter 2

Signing in and the screen layout

You open the application in a web browser at the address given by your administrator. Above the form is the instance mark — an icon and a name. You sign in with your e-mail address and the password received from the administrator; capitalisation in the address does not matter.

After signing in the screen splits in two. On the left is the navy menu, on the right the content of the selected page. In the top right corner you can see your name and a circle with your initials, which opens the user menu. At the bottom of the side menu is the application version number — a link to the change history — together with information about the maker.

Collapsing the menu

Clicking the instance mark at the top of the menu collapses it to icons only, leaving more room for content. Clicking again expands it. The choice is remembered between sessions, so a menu collapsed once stays collapsed after the next sign-in too.

The menu under your initials

  • Profile — your own account details and password change.
  • User manual — this document, opened directly in the application; it can also be downloaded as a PDF.
  • Sign out — end of work.

Side menu entries

  • Dashboard — the start screen with a numeric summary and activity charts.
  • Files — the folder and document explorer.
  • AI chat — questions about document content.
  • Search — the search tool working on descriptive fields.

Below there is a rule labelled ADMINISTRATION, and under it a part visible only to an administrator: Users, Access list, Document schemas, File queue, Answer log and Settings. The same entries also appear as a tab bar at the top of every administrative screen.

At the bottom of the menu there is one more tile, Need help?, with a Contact support button — it leads to the technical support request form (see the separate chapter). When the menu does not fit on a short screen, only the list of entries scrolls; the help tile and the footer stay where they are.

TipAfter a period of inactivity the application signs you out automatically — a safeguard in case a session is left open on a shared computer. The administrator sets the length of that period; regardless of it, a session has a hard limit of twelve hours.

Chapter 3

Dashboard

The Dashboard is the start screen. It shows the state of the document base in figures and charts, and everything on it concerns the selected time range — the drop-down list in the top right corner, with options of 7, 30 and 90 days. One choice governs the whole screen, so the tiles and the charts always speak about the same period.

The tiles at the top

Four tiles give the number of accounts, folders and documents, and the share of documents already processed. Under the figure there is sometimes a second line comparing it with the previous period, for example ↑ 12.6% against the previous 30 days.

TipA missing comparison line does not mean a fault. The application does not show a percentage change when the previous period was too thin for a percentage to mean anything — growth “of 400%” from one document to five is a true and useless number.

Charts

Two charts show daily activity: the number of documents processed and the number of questions put to the chat. Hovering the cursor shows the exact value for a given day.

Recently added documents and user activity

The two panels under the charts show the five most recently uploaded documents and a summary of account activity in the selected period — how many files someone uploaded and how many questions they asked. Accounts with no activity at all do not clutter the list; their number is given underneath.

Quick actions, storage and server status

The bottom row holds three panels. Quick actions lead straight to the most frequent tasks. Storage shows how full the server disk is — note: the whole disk, shared with the other services, which is why the size of the documents alone is given separately below. System status says whether the application, the database, the document parser and the file store are running.

TipThe Parser row shows whether the language model is busy at that moment. “Model idle” means a new question or document will be handled straight away; when the model is computing, a chat answer may have to wait a while.

Chapter 4

Your account and the manual

The circle with your initials in the top right corner opens a menu with three entries: Profile, User manual and Sign out. The menu closes with the Escape key or with a click beside it.

The Profile page

The Profile page shows the account details: display name, full name, e-mail address, assigned role, account status and the date of the last sign-in.

The Edit details button turns the first three entries into form fields. You save with Save and back out with Cancel.

  • Display name — appears in the greeting, in the initials and in administrator summaries. It is not used for signing in, so you may change it freely.
  • Full name — the complete form, used on the Profile page and in the menu.
  • E-mail address — this is the address you sign in with. After changing it, the next sign-in uses the new address.
NoteYou do not change your own role or account status — the administrator does. If the e-mail address or name you enter is already taken by another account, the application says so plainly and does not save the change.

Changing the password

The password is changed on a separate Password card, with the Change password button. The form asks for the password currently in use and for the new one twice over. The new password must be at least eight characters long and differ from the current one.

After a successful change the application signs you out and shows the sign-in screen — this is deliberate: you check straight away that the new password works.

Help

The User manual entry opens the Help page with this document directly in the application, with no hunting for a file on disk. At the top of the page there are two buttons: Open in a new tab and Download PDF. An administrator sees the full edition, other accounts see the user edition, which describes only the screens they have access to.

Chapter 5

Browsing documents

The Files screen is the document explorer. At the top is the navigation path, beginning at the Root folder — clicking any of its elements takes you back to that level. Below there are two cards: Folders and Files.

Two views

Both folders and files can be viewed as a list or as tiles — the switch sits in the header of each card, and the choice is independent for folders and for files. The list holds more information at a glance; tiles are handier when you are looking for a document “from visual memory”.

List columns

The file list shows the file type, name, size, the category recognised by the application and the date added. The category is the kind of document — an order, a procedure, an application form — and it is usually what helps you find the right file. Documents the application has not assigned to any category carry the word unrecognised in that column.

Searching and paging

The Search files box above the list filters documents by name within the current folder. Under the list is the number of documents and a choice of how many entries to show per page (10, 25, 50 or 100).

NoteThe application fetches at most 200 documents from a folder at a time. When a folder holds more, a red note about it appears under the list — you then need to narrow the search or go into a subfolder. The list never hides documents silently.

Document details

Clicking a row opens a window with the details: file type, size, processing status, date added, folder, the account that uploaded the document and the recognised category. From that window you can download the document, and PDF files can also be previewed in a new tab.

Chapter 6

Adding documents

Documents are added with the Upload files button in the top right corner of the Files screen. They go into the folder currently open — which is why you first go into the right folder and only then upload. The target folder is always spelled out in the upload window.

You can select several files at once. The application then shows progress separately for each of them, and a summary at the end: how many files were uploaded and how many ended in an error.

Allowed formats

The application accepts PDF, DOCX, ODT and XLSX files, each up to 100 MB in size. The list of formats is visible in the upload window and comes straight from the application settings — if the administrator changes it, the window will show the new list and the system file picker will filter out the remaining extensions.

NoteThe file name matters. The application uses it as a hint when recognising the kind of document, and it also displays it in search results and in chat answers. A name such as “Order no. 8-2023 remote work.pdf” is far more useful than “scan_0001.pdf”.

Chapter 7

Housekeeping: folders, moving, deleting

Keeping the document collection in order is the administrator's task. All the operations described below are carried out on the Files screen.

New folder

The New folder button creates a subfolder in the place where you currently are. The window shows which permissions the new folder will inherit from its parent — this is a read-only view; permissions are changed later with the padlock icon.

Renaming a folder

The pencil icon on a folder tile (visible on hover) changes its name. The change covers the path of that folder and of all its subfolders; files and permissions stay assigned unchanged.

Moving documents

A single document is moved with the folder-and-arrow icon in its row. The list of target folders is arranged alphabetically and contains only those you have write access to.

Operations on several documents at once

Selecting documents with the checkboxes on the left reveals the Act on selected button with two options: Move to another folder and Rename to match category (described in the chapter on document recognition). The checkbox in the header selects the documents on the current page, not the whole list.

Deleting

The bin icon deletes a document together with its passages in the knowledge base — once deleted, it stops appearing in chat answers. Deleting a folder moves its documents to the root folder, so nothing is lost along with the folder.

NoteDeleting a document cannot be undone from within the application. Before deleting a larger batch it is worth downloading a summary of the documents to a spreadsheet — the Download this list as XLSX button on the Search screen does exactly that.

Chapter 8

Permissions and roles

Access to documents follows from the role an account belongs to and from the permissions granted to that role on folders. Permissions are not granted to individual people — thanks to which, when someone changes post, it is enough to change the account's role instead of correcting dozens of folders.

Two levels of access

  • Read — the role sees documents in the folder, may open and download them, and their content takes part in chat answers.
  • Write — in addition, new documents may be uploaded, moved and deleted.

Inheritance

A permission granted on a folder covers its subfolders as well. In the permissions window, inherited entries are described as (inherited from parent) and cannot be removed there — they are changed on the parent folder. On a subfolder, access can only be widened, for example Read raised to Write.

Managing roles

Roles are defined on the Access list screen with the Add role button. A role can also be renamed and deleted. Three rules the application enforces are worth knowing:

  • Renaming changes the label only. The internal role code stays the same, so permissions granted earlier and account assignments keep working unchanged.
  • System roles cannot be deleted — Administrator and Guest are part of how the application works.
  • Deleting a role that has accounts in it requires naming a replacement role. The application will move those accounts into it so that none is left unassigned.

The whole picture

The Access list screen shows a summary of all roles and folders in one place, so you can see at once who sees what. Clicking a folder takes you straight to it in the explorer.

NoteThe administrator sees every folder regardless of the permissions granted. Documents lying in the root folder, outside any folder, are visible only to the administrator — which is why a document uploaded “to the root” will not appear to anyone else, either in search or in chat.

Chapter 9

AI chat — questions about document content

The AI chat screen is where you ask questions about the content of documents. It splits into three parts: the list of earlier conversations on the left, the conversation window in the middle and a link to the search tool on the right.

You type the question into the box at the bottom and confirm it with Enter; Shift+Enter moves to a new line. The answer appears gradually, word by word — you can interrupt it with the Stop button.

Where the answer comes from

Under every answer there is a list of documents used in the answer. Each entry gives the reference number, the file name, the page and the kind of document; clicking it opens the source document. The numbers in the badges match the references in the body of the answer, so you can see which sentence came from where.

Below there is sometimes a note along the lines of 7 further documents were checked but not used, together with a button that unfolds their list. These are documents the application looked through while searching for an answer but found nothing on the subject in — worth a look when an answer seems incomplete.

When the documents hold no answer

The application answers solely on the basis of the documents uploaded. If it finds no information, it says so plainly instead of making things up. An answer of “no information on this subject was found in the documents” is therefore a statement about the document collection, not a fault.

Questions asking for a list of documents

A question such as “show all orders from 2023” is recognised by the application as a request for a listing, not for an answer drawn from content. It then replies with the sentence “I found N documents”, a list of those documents and a Download this list as XLSX button.

Conversations

Every conversation is saved in the list on the left and you can return to it. The New chat button starts a conversation from scratch. This matters: within a single conversation the application takes earlier questions into account, so when the subject changes it is better to start a new one.

TipQuestions asking “the same thing in other words” are often effective. If the first answer is general, it is worth asking about a detail — the application then searches within the documents indicated in the previous answer.

Under the answer there is a request for a rating. Ratings go to the Answer log screen in the administrative section and serve to improve how the application works — it is worth encouraging users to make use of it.

Chapter 10

Search on descriptive fields

Search is a separate screen in the menu. It answers questions about the structure of the collection: “all orders from 2023”, “applications signed by a particular person”. Chat answers questions about content — the two routes are deliberately not mixed.

Ask in your own words

The simplest way is to type the question in plain language into the box at the top. The cursor is placed there as soon as you enter the screen. The application recognises the kind of document and the conditions from your question, fills the form below with them and shows the results straight away. The recognised filter can then be corrected by hand and searched again.

The form

The form consists of a kind of document and any number of conditions. A condition is a descriptive field, an operator (contains, equals, from, to, after, before) and a value. The list of available fields depends on the kind of document selected — it comes straight from the document schemas.

Results

The results look exactly like the list of documents under a chat answer: number, file name and kind of document. There is no page here — the result is a whole file, not a passage of one. Clicking opens the document. Above the list is a Download this list as XLSX button — the spreadsheet contains the complete set of descriptive fields, with the columns in the order set in the document schema.

TipThe search works on descriptive fields, not on content. A document from which the application failed to extract a number or a date will not appear in results filtered on those fields — it will, however, be found through chat.

Chapter 11

Administration

The administrative section sits in the menu under the ADMINISTRATION rule and is visible only to administrator accounts. The same entries are repeated by the tab bar at the top of each of those screens.

Users

Creating accounts, changing roles, deactivating and resetting passwords. An account signs in with its e-mail address; the display name serves only for showing in the interface and may repeat.

Access list

A summary of the permissions of all roles together with the management of the roles themselves — described in the chapter on permissions.

Document schemas

Kinds of documents together with their descriptive fields, recognition criteria and file-name pattern. This is the screen that most strongly affects how well the search tool works — described in the chapter on document recognition.

File queue

A view of processing: what is waiting, what is under way, what failed. Here you can see the recognised kind of document and the extracted fields, which makes it the first place to look when a document is not showing up in results.

Answer log

Ratings given to chat answers together with the question, the answer and the documents indicated. It serves to catch questions the application answers badly — every such entry is a hint about which document is missing or which schema needs correcting.

Settings

The screen splits into three parts.

  • Application identity — the instance name, the colour of the caption and the icon. The icon must be a square PNG or SVG file (128×128 px recommended as a minimum); it appears at the top of the menu and on the sign-in screen. The preview beside it shows exactly what the user will see.
  • Integrations and session — the processing and chat webhook addresses, the list of allowed file extensions and the time to automatic sign-out.
  • Outgoing mail — the SMTP server details and the support address. Without them the “Contact support” form will reply plainly that sending is not configured.
NoteThe list of allowed extensions must match what the processing workflow handles. An extension added here but not handled there will mean the file is accepted but never processed.

Change history

The version number at the bottom of the side menu leads to the list of changes in successive releases of the application. That page is available to everyone signed in.

Chapter 12

How the application recognises documents

After a document is uploaded the application tries to establish what it is and to extract descriptive fields from it. It does so on the basis of document schemas — definitions of kinds of documents that the administrator sets up on a separate screen.

What a schema is made of

  • Name and identifier of the kind of document, for example “Order”.
  • Classification criteria — hints in plain language on how to tell this kind of document.
  • Header fields — what to extract from the content: number, date, title, signing person. The order of the fields sets the order of the columns when exporting to a spreadsheet.
  • File-name pattern — optional, described below.

Field types

Every field has a type: Text, Date, Number, Amount or Value list. The type is not decoration — it decides what you can do with the field. Dates allow filtering by ranges, and amounts go into the spreadsheet as numbers with decimals, so the column adds up (even when the document wrote it as “1,234.56 PLN”).

File names from recognised fields

Every kind of document may have a file-name pattern, for example {type}-no-{document_number}-{date}. The application then proposes names matching the content of the document instead of “scan_0001.pdf”. An empty pattern means that no names are proposed for that category.

Names are given in batches: on the Files screen you select the documents and choose Act on selected → Rename to match category. The window first shows a summary of old name → new; every entry can be corrected by hand or unticked. Nothing happens without that preview.

The previous name is remembered and visible in the document details, so the change can be traced back and the document stays recognisable to anyone who remembers it under the old name.

When recognition fails

A document the application has not assigned to any kind carries the category unrecognised. It remains searchable through chat — it will not, however, be found by the search tool filtering on fields. The most frequent causes are a poor-quality scan or the absence of a schema describing that kind of document.

TipThe file queue shows which fields were extracted from each document. If a field is empty for many documents of the same kind, it is usually worth correcting the classification criteria or the field name in the schema.

Chapter 13

A request to technical support

The Need help? tile at the bottom of the side menu leads to the technical support request form. It is enough to describe the matter and send it — the sender and the instance are attached automatically, and the reply goes to the e-mail address assigned to the account.

The request goes by mail, not through the document processing mechanism. This is deliberate: a processing failure must not cut off the route for reporting a problem, because that is exactly when reports are needed most.

TipIt is worth writing what you were doing and what you expected, not just “it does not work”. The name of the screen, the wording of the question put to the chat or the name of the document shortens the diagnosis by several exchanges of messages.

Chapter 14

Good practice

  • Give documents names that say what they are — this helps both recognition of the kind and later searching.
  • Upload documents into a thematic folder, not into the root folder.
  • Check the status after uploading: only Processed means the document is answering questions.
  • When the subject changes, start a new chat so that earlier questions do not affect the answer.
  • For formal matters, open the source document indicated under the answer.
  • Grant permissions to roles on the highest folder you can — subfolders inherit them automatically.
  • After a larger batch of documents, go through the File queue and correct wrongly recognised kinds.
  • Deactivate rather than delete the accounts of people who have left — this preserves the history of operations.

Chapter 15

Limitations and development plans

This instance is a demonstration version, running on sample documents. Apart from that it is exactly the same application as the client deployments. The limitations below are known and scheduled for removal.

  • The application answers solely on the basis of documents uploaded into the base — it knows neither regulations nor knowledge from outside them.
  • A chat answer is a summary of passages of documents. For formal matters, the source document indicated under the answer prevails.
  • Recognition of the kind of document and of descriptive fields works well on documents of typical build; unusual documents may need the kind corrected by hand.
  • Document preview opens the PDF file in a new browser tab. A viewer built into the application — opening the document straight at the page indicated — is planned.
  • Links between documents (for example an order and its attachments) are not yet presented in the interface.
  • The search on descriptive fields does not search document content — that is what chat is for.

Every change is described in the Change history available from within the application, from under the version number at the bottom of the menu.

Chapter 16

Frequently asked questions

Below are the situations most often reported on first contact with the application.

SituationWhat to do
I uploaded a document but the chat does not know it.Check the status on the file list. Until it reads Processed, the document does not take part in searching. With long documents, processing takes a few minutes.
The chat replies that it found no information.Most often the question concerns a document that is not in the base, or the document is not processed yet. It is also worth asking the question differently — in a full sentence.
I cannot see a folder my colleague is talking about.Folders are shared with roles. If access is missing, ask the administrator to grant permission to that folder.
The application signed me out by itself.After a period of inactivity set by the administrator, the session expires. Simply sign in again.
I cannot upload a file — the picker does not show it.The application accepts PDF, DOCX, ODT and XLSX formats. Files in other formats must first be saved in one of these.
I cannot sign in with my user name.Only the e-mail address assigned to the account is used for signing in. The user name is merely a display name.
I forgot my password.The administrator sets a new password in the Users module. After signing in it is worth changing it to your own on the Profile page.
Where do I find this manual in the application?Under the circle with your initials in the top right corner, the Help entry. From there it can also be downloaded as a PDF.
A document was recognised as the wrong kind.In the File queue you can point to the right kind by hand; the application will immediately extract the fields anew.
A new employee sees no documents at all.The account has a role, but the role does not yet have permissions to any folder. Permissions are granted in the Files view, with the key icon beside a folder.
I want to add a new kind of document with fields of my own.The Document schemas page in Administration is there for that.
